# Git Rules

## Do Not Commit or Push Unless Asked
Only run `git add`, `git commit`, or `git push` if the user explicitly asks you to. This includes amending commits. Wait for explicit instruction.

## Commit Message Format

Use the ticket ID from the current branch or task context if it exists. Use present tense verbs: Fix, Add, Remove, Refactor, Update, Improve.
If there are multiple types of changes in the commit, list using Markdown "- " bullets. 
Don't make commit messages too long, though. Use the minimum amount of words needed to fully convey changes made.

## Protected Branches
Always use feature/bugfix branches. Committing directly to `dev` is strictly forbidden. Do not force push to shared branches.
